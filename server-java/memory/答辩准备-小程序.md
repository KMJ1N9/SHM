# 小程序课程答辩准备

## 项目一句话介绍

> 基于 **uni-app (Vue 3)** 开发的校园二手交易微信小程序，覆盖发布/下单/IM 聊天/评价/举报完整交易闭环，双后端可切换。

---

## 技术栈速查（前端）

| 层级 | 技术 | 用途 |
|------|------|------|
| 框架 | uni-app + Vue 3 Composition API | 跨端开发 → 微信小程序 |
| 状态管理 | Pinia | 用户信息/聊天/应用全局状态 |
| 样式 | SCSS + 设计令牌(tokens) | 8pt 间距系统 + 品牌色 + 组件样式 |
| HTTP | uni.request 统一封装 | Token 自动附加 + 过期无感刷新 + 错误拦截 |
| IM | 腾讯云 IM SDK | 买家卖家实时聊天 |
| 图片 | COS SDK | 前端直传对象存储，不经后端 |
| 构建 | Vite (uni-app 内置) | 编译 → 微信开发者工具 |

## 答辩必讲亮点（5 个）

### 1. 组件化架构

> "我封装了 6 个通用组件：ProductCard 商品卡片、FilterSidebar 筛选侧边栏、ImageUploader 图片上传器、StarRating 星级评分、AppNavbar 导航栏、EmptyState 空状态。所有页面共用这套组件，保证视觉一致。比如 ProductCard 在首页、搜索结果、我的发布三个地方复用，只需传不同 props。"

**展示建议：** 打开 `components/` 目录，挑 ProductCard.vue 展示 props 定义和 slots。

### 2. API 层设计 + Token 无感刷新

> "我封装了统一的 HTTP 请求层（api/index.js），所有请求自动带上 Bearer Token，业务代码只需 `get('/orders', params)` 一行调用。当返回码 1002（Token 过期）时，拦截器自动用 refreshToken 换新 Token 并重试原请求。如果有多个请求同时过期，不会并发刷新——第一个请求去刷新，其他排队等待，刷新完了一起重试。"

**展示建议：** 打开 `api/index.js` 的 `request()` 函数，展示 `isRefreshing` + `refreshQueue` 的并发控制逻辑。

### 3. IM 即时通讯（腾讯云 IM SDK）

> "买家拍下后可以直接和卖家聊天。我集成了腾讯云 IM SDK——登录时后端返回 UserSig 完成 IM 鉴权，会话列表实时更新，收到新消息有未读角标。后端通过 IM REST API 推送系统消息，比如'对方已发起面交，请确认'。"

**展示建议：** 两个账号同时在真机上演示实时聊天，展示消息收发。

### 4. 图片直传 COS

> "图片不经过后端——前端先从后端拿到 COS 临时密钥（STS），然后用 COS SDK 把图片直传到腾讯云对象存储。上传完成后拿到图片 URL 提交给后端。这样后端不用处理图片流，不占用服务器带宽。ImageUploader 组件封装了选图 → 压缩 → 上传 → 预览的全流程，支持多图上传和 5MB 大小校验。"

**展示建议：** 打开 `components/ImageUploader.vue` 展示上传逻辑，在发布商品页真机演示选图上传。

### 5. 设计系统（SCSS + 令牌）

> "我建了一套设计令牌（tokens.scss）：品牌色 $color-primary / $color-primary-gradient，8pt 间距系统（$space-xs ~ $space-page），统一圆角 $radius-card/$radius-full，统一阴影 $shadow-card/$shadow-button。所有 25 个页面和 6 个组件都引用这些令牌，不写硬编码的色值或间距，改一套令牌全局生效。"

**展示建议：** 打开 `styles/tokens.scss` 展示令牌定义，再打开任意页面展示引用方式（`@import '@/styles/tokens.scss'`）。

## 可能被问的问题

**Q：为什么用 uni-app 而不是原生微信小程序？**
> uni-app 写 Vue 3，一套代码能编译到微信/支付宝/字节等多个平台。而且 Vue 的 Composition API + Pinia 开发体验比原生小程序好很多，组件化也更成熟。

**Q：uni-app 编译到小程序有什么坑？**
> 不支持 web 的 DOM API（没有 document/window），CSS 动画性能不如原生，v-for 的 key 要特别注意，部分 CSS 选择器不被支持。但常规业务足够用。

**Q：双后端是什么意思？**
> 我写了两套后端——Node.js Express 和 Java Spring Cloud 微服务——但它们的 API 路径、响应格式、错误码完全一致。前端改一行 BASE_URL 就能切后端，方便对比学习和性能测试。

**Q：Pinia 和 Vuex 有什么区别？**
> Pinia 是 Vue 3 官方推荐的状态管理，比 Vuex 更简洁——没有 mutations，直接用 actions 改状态，TypeScript 支持更好。

**Q：小程序性能优化做了什么？**
> 组件按需注入（lazyCodeLoading）、图片懒加载、订单列表分页加载（游标分页）、SCSS 变量复用减少重复样式、api/ 层统一管理避免散落请求。

**Q：登录为什么是 Mock？**
> 微信 getPhoneNumber 需要小程序通过微信认证（300 元/年），当前未认证。开发环境用 Mock 登录绕过，审核时改为手动输入手机号+验证码方式。
