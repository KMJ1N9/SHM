# 答辩准备 — 商品发布功能

> 我主要负责**商品发布模块**，从选择图片→填写信息→预览提交的全流程。

---

## 功能入口

首页底部 TabBar → 中间 + 号 → 商品发布页（三步骤向导）

---

## 三步骤发布流程

```
Step 0: 上传图片          Step 1: 填写信息          Step 2: 确认发布
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  ImageUploader│  →   │  ProductForm │  →   │ ProductPreview│
│  选1-6张图片  │      │  商品名称     │      │  预览全部信息  │
│  格式校验     │      │  分类/成色    │      │  确认后提交    │
│  大小校验     │      │  原价/售价    │      │  跳转首页/详情 │
│  缩略图预览   │      │  交易地点     │      └──────────────┘
└──────────────┘      │  议价/描述    │
       ↓              └──────────────┘
  chooseAndUpload()           ↓
  直传 COS / 本地         validateForm()
                      前端参数校验
```

## 必讲亮点（3 个）

### 1. 图片上传 — 前端直传 + 本地兜底

> "图片不经过后端服务器。我封装了 ImageUploader 组件负责选图和预览，实际上传由 cos.js 处理。流程是：先从后端获取 STS 临时密钥 → 前端拿密钥直传腾讯云 COS。开发环境 COS 配置为占位符时，自动回退到服务器本地上传。上传完成后拿到 URL 列表，随表单一起提交。"

**展示建议：**
- 打开 `components/ImageUploader.vue` 展示校验逻辑（格式 MIME+扩展名双重检查，大小 5MB 限制）
- 打开 `utils/cos.js` 展示 `chooseAndUpload()` 函数，mock 分支和 COS 分支

### 2. 表单校验 — 前后端双重校验

> "前端在下一步时做完整校验：商品名称非空、分类和成色必须选、售价必须大于 0 且不能高于原价、交易地点非空。后端还有 Joi (Node.js) 或 @Valid (Java) 做二次校验——因为 HTTP 请求可以被绕过，前端校验只是用户体验，安全校验必须在后端。"

**展示建议：**
- 前端：publish.vue 的 `validateForm()` 函数
- 后端：server/routes/product.js 的 Joi schema，展示 required/valid/min/max 规则

**校验对照表：**

| 字段 | 前端校验 | 后端校验 |
|------|---------|---------|
| 标题 | 非空，trim | Joi: required, min(1), max(200) |
| 分类 | 必须选择 | Joi: required |
| 成色 | 必须选择 | Joi: valid('全新','95新','9成新','8成新','7成新及以下') |
| 原价 | >= 0 | Joi: required, min(0) |
| 售价 | > 0 且 <= 原价 | Joi: required, min(0) |
| 交易地点 | 非空 | Joi: required, max(200) |
| 图片 | 1-6 张 | Joi: items(uri), min(1), max(6) |

### 3. 敏感词过滤 + 信誉分门槛

> "发布商品时有双重安全防护。一是敏感词过滤——标题、描述、交易地点都会过 DFA 算法检查，命中敏感词直接拒绝发布。二是信誉分门槛——信誉分低于 60 的用户不能发布商品，通过取消订单、被举报等行为扣分来约束用户行为。"

## 代码结构（口述用）

```
publish.vue (主页面)
  ├─ ImageUploader   → 选图 + 上传 + 校验
  ├─ ProductForm     → 表单输入（名称/分类/成色/价格/地点/描述）
  └─ ProductPreview  → 发布前预览 + 确认提交

前端校验: validateForm()  → 全字段规则
后端校验: Joi schema / @Valid → 参数化 SQL → 防注入
敏感词:   DFA 算法过滤标题+描述+地点
信誉分:   creditScore >= 60 才可发布
```

## 可能被问的问题

**Q：为什么图片不经过后端？**
> 减少服务器带宽压力。后端只负责签发临时密钥，前端拿到密钥直接传到 COS。密钥 30 分钟过期，且限制上传路径 `user_{userId}/` 和文件类型，保证安全。

**Q：ImageUploader 组件怎么设计的？**
> 只负责选图和预览，不负责上传。通过 `@update:files` 事件把文件列表传给父组件，父组件调用 `cos.js` 的 `chooseAndUpload()` 实际上传。这样组件职责单一，可复用于发布页和举报页。

**Q：怎么防止重复提交？**
> 提交按钮点了之后设 loading 状态，按钮 disabled，防止手快连点。后端用幂等键（idempotent_key）防重复创建。

**Q：编辑商品和发布商品是同一个页面吗？**
> 是，publish.vue 通过 `onLoad(options.id)` 判断——有 id 就是编辑模式，加载现有数据回填表单；没有 id 就是新建。编辑时校验 ownership（只能编辑自己的商品），且 sold/frozen/deleted 状态不可编辑。

## 演示流程（2 分钟）

1. 点击底部 + 号进入发布页
2. 选 2-3 张图片 → 下一步
3. 填写商品信息 → 下一步
4. 预览确认 → 点发布
5. 跳转首页，刚刚发布的商品出现在列表里
6. 点进商品详情，展示完整信息
