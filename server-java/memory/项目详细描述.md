# 校园二手交易平台 — 项目详细描述

## 项目背景

广州应用科技学院肇庆校区 C2C 校园二手交易平台，面向在校学生提供安全可信的闲置物品面交换服务。传统校园二手交易依赖 QQ 群、微信群、贴吧等渠道，存在交易效率低、信任缺失、缺乏售后保障等痛点。本项目提供从商品发布、即时通讯、订单交易到信用评价的完整闭环。

### 备选后端

同时维护一套 **Node.js Express 5 层架构**后端（`server/`），与 Java 微服务共享完全相同的 API 契约：

- 相同路径（43 个端点）
- 相同响应格式 `{code, message, data}`
- 相同错误码体系（30 枚举）
- 相同 JWT 鉴权行为
- 前端改一行 `BASE_URL` 即可切换后端

## 关键技术点

### 1. 微服务拆分与网关

- 4 个独立微服务（Gateway/Core/Admin/IM-Connector）+ 1 个共享库（Common）
- Gateway 做统一入口：路由转发 + JWT GlobalFilter 鉴权 + CORS
- 鉴权后通过 `X-User-Id` 请求头透传用户身份给下游
- 下游 `OncePerRequestFilter` 做二级防御（存在性/封禁/tokenVersion/Redis黑名单）

### 2. 高并发与流控

- Redis Cache-Aside 缓存商品列表和用户信息
- Sentinel 对高频接口做 QPS/线程数/RT 多维度限流
- Feign 调用失败走 Sentinel Fallback 降级
- Redisson RLock 分布式锁保障订单并发安全

### 3. JWT 双 Token 认证

- Access Token（15 分钟）+ Refresh Token（7 天）
- Token 过期 → 前端拦截器自动无感刷新
- 并发刷新排队机制（isRefreshing + refreshQueue）
- TokenVersion 机制实现用户封禁即时生效

### 4. 订单状态机

- 完整生命周期：pending → met_pending → met → completed → cancelled
- 面交双向确认：一方发起、另一方确认、双方同时发起自动完成
- MyBatis SELECT ... FOR UPDATE 悲观锁防并发状态错乱
- Seata @GlobalTransactional 跨服务分布式事务

### 5. 全链路追踪

- Gateway WebFilter 生成 traceId/spanId → 注入 MDC
- Feign 拦截器传播 traceId 到下游请求头
- 所有日志带 [traceId,spanId] 前缀
- Zipkin 可视化调用链

### 6. 监控体系

- Prometheus 采集 Actuator 指标
- Grafana 5 面板：JVM 堆内存/GC/DB 连接池/Redis 命中率/磁盘健康
- 聚合健康检查端点 `/api/health`

### 7. 自动化测试

- Python 测试脚本覆盖 14 个核心 API（登录→商品→订单→面交）
- 支持双后端一键切换对比
- 回归测试从手动 20 分钟降至 3 秒
