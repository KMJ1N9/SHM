# 验证码登录改造计划

## 背景

微信 `getPhoneNumber` 需要小程序通过微信认证（300 元/年），当前 AppID `wx0c4d54c24d540539` 未认证，审核时手机号授权功能不可用。

改为**用户手动输入手机号 + 验证码**登录，避免认证年费。

## 方案概述

```
[登录流程]
用户输入手机号 → 点"获取验证码"
  → 后端生成 6 位随机码 → 存入 Redis (TTL=5min, 60s 发送限流)
  → 开发环境：验证码打印到服务端日志
  → 生产环境：通过腾讯云短信 API 发送（几分钱/条）
用户输入验证码 → 点"登录"
  → 后端校验 Redis 中的验证码
  → 查找/创建用户 → 签发 JWT 双 Token
```

**接口设计：**

```
POST /api/auth/send-code
Body: { "phone": "13800138000" }
Response: { "code": 0, "message": "success", "data": null }
限流: 同一手机号 60 秒内不可重复发送 (Redis key: sms:rate:{phone})

POST /api/auth/login
Body: { "phone": "13800138000", "code": "123456" }
  - phone 为空 → 走原微信 code 逻辑（向下兼容）
  - phone 以 mock_ 开头 → 走原 mock 逻辑
  - phone 有值且非 mock → 走验证码登录
```

**AuthService 核心逻辑：**

```java
public void sendCode(String phone) {
    // 1. 检查 60s 发送限流 (Redis: sms:rate:{phone})
    // 2. 生成 6 位随机码
    // 3. 存入 Redis: sms:code:{phone}，TTL = 300s
    // 4. 开发环境: log.info("验证码: {}", code)
    // 5. 生产环境: TODO 调用腾讯云短信 API
}

public LoginResponse login(String phone, String code) {
    if (phone == null || phone.isEmpty()) {
        // 原微信 code 流程
    } else if (code.startsWith("mock_")) {
        // 原 mock 流程
    } else {
        // 验证码流程
        String storedCode = redis.opsForValue().get("sms:code:" + phone);
        if (storedCode == null || !storedCode.equals(code)) {
            throw new BusinessException(VALIDATION_ERROR, "验证码错误或已过期");
        }
        redis.delete("sms:code:" + phone);
    }
    // 查找/创建用户 → 封禁检查 → 签发 Token
}
```

**依赖注入：** 需要 `StringRedisTemplate`（core-service 已有 Redis 配置，直接注入）

## Redis Key 设计

| Key | 值 | TTL | 用途 |
|-----|----|----|------|
| `sms:code:{phone}` | 6位验证码 | 300s (5min) | 验证码校验 |
| `sms:rate:{phone}` | "1" | 60s | 发送频率限制 |

## 向后兼容

- 旧版微信手机号授权 code 仍然可用（phone 为空时走原逻辑）
- `mock_` 前缀登录保留，开发环境可用
- 不影响现有用户数据（用户表已有 phone 字段）

## 风险与限制

- 开发环境验证码打印在日志中，无短信成本
- 生产环境需要接入腾讯云短信 API（约 0.045 元/条），需额外配置 `TENCENT_SMS_*` 环境变量
- `GET /api/auth/send-code` 需要加到 Spring Security 白名单
